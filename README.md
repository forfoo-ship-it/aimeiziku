# AI媒资库——视频素材智能检索系统

面向县级融媒体中心编辑的历史素材检索系统。当前已完成视频关键帧索引、AI 画面理解，以及基于 SQLite 画面索引的自然语言检索。

## 技术栈与技术选型

| 层级 | 技术选型 | 用途与选型原因 |
| --- | --- | --- |
| 后端语言 | Python 3.11+ | 生态成熟，适合视频处理、AI 接口与媒资任务编排 |
| Web 框架 | FastAPI + Uvicorn | 提供轻量、清晰、可测试的 HTTP API 和本地/内网服务 |
| 数据库 | SQLite + FTS5 | 单机部署无需独立数据库服务；不支持 FTS5 时自动回退普通全文匹配 |
| 视频处理 | FFmpeg + imageio-ffmpeg | 抽取带准确时间点的关键帧，并计算 SSIM 相似度去重 |
| AI 画面理解 | 独立 VisionProvider + HTTPX | 当前适配 DeepSeek 兼容视觉接口；Provider 结构便于内网替换本地视觉模型 |
| 搜索 | 结构化字段加权 + 同义词扩展 + 强关联过滤 | 对主体、动作、场景、镜头类型和 OCR 进行可解释检索 |
| 页面 | Jinja2 + 原生 HTML/CSS/JavaScript | 避免复杂前端框架，降低县级融媒体内网部署与维护成本 |
| 测试 | Pytest + FastAPI TestClient + Fake Vision Provider | 自动验证上传、抽帧、识别、索引、搜索和目录扫描，不消耗真实 API |
| 部署 | Windows/Linux 本地或内网部署 | 素材和索引保留在部署单位可控环境中 |

## 第一阶段功能

- 仅接收 MP4 视频上传
- FFmpeg 在 `0、5、10……` 秒提取画面
- SQLite 保存视频信息、画面路径和毫秒级时间点
- 左侧浏览关键帧，右侧播放原视频
- 点击关键帧后跳转到对应时间并播放

以上为已经封存的第一阶段能力。

## 第二阶段功能

- 点击“AI识别画面”后逐帧调用独立视觉 Provider
- Base64 在后端直接传递图片，不依赖公开图片 URL
- SQLite 保存待处理、处理中、成功、失败状态和结构化结果
- 页面逐帧显示摘要、主体、动作、场景、镜头类型与 OCR 文字
- 成功帧默认跳过，仅在用户确认“重新分析”后再次调用
- 单帧失败不会阻断后续画面，测试使用 Fake Provider

## 第三阶段功能

- 首页用自然语言检索所有已经成功识别的关键帧
- SQLite 支持 FTS5 时使用全文索引，不支持时自动回退为安全的普通全文匹配
- 对主体、动作、OCR、场景、镜头类型、摘要、文件名和时间点进行加权排序
- 支持“打鼓/击鼓”“横版/横屏”“航拍/俯瞰”等可配置同义词召回
- 业务简称维护在 `app/search_synonyms.json`，例如“展示牌/展牌/展示板/展板”组内可以互相召回，无需重新识别视频
- 新识别画面会在同一次视觉调用中生成主体、动作、场景和镜头类型的受约束检索别名；原始AI结果保持不变，别名只写入搜索索引，不增加额外API调用次数
- 识别成功、重新识别和索引重建共用 `app/search_vocabulary.py`，确保未来视频和已有数据采用同一套词汇扩展规则
- 多个不同概念采用强关联过滤，必须在同一关键帧中同时成立；例如“竖屏无人机”不会返回只有竖屏或只有无人机的画面
- 搜索结果显示结构化画面信息、相关度、命中字段和命中理由
- 点击结果后自动切换对应原视频，跳至关键帧时间点并播放
- AI 识别成功或重新识别后自动更新索引；重复更新不会产生重复数据
- 搜索只读取 SQLite，不提取关键帧，也不会调用 DeepSeek 或产生新的视觉识别费用

## 第四阶段功能

- 在首页填写本机素材目录，递归监测目录及其子目录中的 MP4
- 添加目录后立即扫描，此后按 30 秒、1 分钟、5 分钟或 15 分钟周期自动扫描
- 使用完整文件 SHA-256 内容指纹去重；文件改名或移动后也不会重复导入
- 源文件只读，系统把副本保存到受控上传目录后再抽帧
- 显示发现、已处理、新增、跳过、失败、当前文件和当前阶段进度
- 视频显示“待AI识别、AI识别中、已建立索引、部分完成、处理失败”等状态
- 默认不自动调用 DeepSeek；只有勾选“自动进行AI画面识别”才会处理新视频
- 已成功建立索引的视频在以后扫描中直接跳过；只有人工确认“重新分析”才会重复调用视觉模型
- 搜索结果按素材年月分组，卡片悬浮或键盘聚焦时显示完整帧信息
- 关键帧、搜索缩略图和播放器按真实宽高自动适配横屏或竖屏，竖屏画面完整显示不裁切
- 素材日期优先取文件名中的 `YYYYMMDD`，其次取源文件修改时间，最后使用导入时间
- “全部视频素材”以首帧缩略图网格显示数据库中的所有视频，不再只展示最近几条；接口按最多 500 条分页读取，页面会继续加载到完整总数
- 视频卡片显示文件名、素材年月、总帧数、已识别帧数和索引状态；缺少本地首帧的旧记录会显示占位提示
- 素材库支持全选、只选未识别、清空选择和批量识别，并显示当前视频及逐帧总体进度
- 普通“识别所选”自动跳过已建立索引的视频；“重新分析所选”必须人工二次确认后才会再次调用视觉模型
- 点击视频卡片中的“已识别画面”，可在素材管理后台底部查看所属关键帧及结构化识别信息
- 已识别关键帧支持人工修改摘要、主体、动作、场景、镜头类型、OCR和置信度；保存后立即同步SQLite搜索索引，不调用视觉API，并标记为“已人工修正”
- 新导入视频仍按5秒记录关键帧，并使用FFmpeg SSIM比较相邻代表帧；相似度达到99.5%的固定画面标记为“相似画面已跳过”，不重复调用视觉API或建立重复搜索结果
- 相似帧仍保留原时间点和缩略图供后台核查；已有视频不会自动清理或改变现有索引
- 如相似帧中存在需要保留的细微变化，可在后台点击“仍然分析此帧”；系统会明确确认费用，并只对所选帧调用一次视觉API
- 素材管理后台采用“监测目录或盘符 → 实际素材文件夹 → 文件夹内视频”三级管理，不一次显示全部视频；第二层只列出已经发现并入库视频的文件夹
- 若监测整个盘符，先显示该盘符，再显示盘符下各个已入库素材文件夹；嵌套监测目录按最具体的监测项归类，避免同一文件夹重复出现
- 点击具体素材文件夹后才分页加载其中的视频，批量选择和识别仅作用于当前文件夹
- 手动上传的视频统一归入“历史视频上传”，自动扫描导入的视频保留并显示原始素材文件夹路径
- 播放器提供“打开视频所在位置”：服务器本机通过 `localhost` 或 `127.0.0.1` 访问时可直接在文件管理器中定位视频；文件夹导入优先定位原始文件，手动上传定位受控副本

“停止监测”只移除目录配置，不删除源视频、已导入副本、关键帧或搜索索引。

“打开视频所在位置”只能操作数据库中已有的视频，并默认限制为服务器本机请求。内网其他电脑无法通过普通网页直接打开服务器本地磁盘；如需在编辑电脑上定位文件，应将源素材目录挂载为各终端都能访问的共享路径，或另行安装受控桌面辅助程序。

> 监测目录必须是运行服务的这台电脑可以直接访问的本地路径。当前阶段仍不包含 NAS 专用同步协议。

当前仍不包含 ASR、同期声检索、Embedding、向量数据库、多模型切换界面、NAS 同步、权限、自动剪辑或公网部署。

## 画面搜索

在首页顶部输入 2 至 200 个字符开始搜索。接口也可直接调用：

```text
GET /api/search?q=龙舟鼓手击鼓的横屏镜头&limit=20
```

`limit` 可设为 1 至 50。返回结果中的 `score` 是检索相关度，不是 AI 识别准确率。无结果时返回空列表；空查询返回 400。

检索采用“同义词组内可替代、不同概念之间必须同时命中”的规则。例如“竖版航拍”可匹配“竖屏＋无人机”，但横屏航拍和竖屏采访都会被排除。

已有第二阶段数据会在应用启动时自动补建索引。开发维护时可手动重建全部搜索索引：

```powershell
.\.tools\Python314\python.exe -m app.rebuild_search_index
```

## DeepSeek 配置

复制 `.env.example` 为本地 `.env`，只在本机填写 API Key：

```ini
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_VISION_MODEL=deepseek-v4-flash-vision-exp
```

`.env` 已被 Git 忽略，API Key 只在后端读取。请勿将真实密钥写入源码、测试或聊天内容。

> 注意：截至 2026-08-28，DeepSeek 官方公开文档尚未列出上述实验视觉模型，且公开 API 文档未声明支持图片输入。真实调用能否成功取决于账号是否具备该实验模型权限。

- Git 2.53.0.windows.3

## 启动

在 PowerShell 中运行：

```powershell
.\.tools\Python314\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器访问 <http://127.0.0.1:8000>。

### Windows 安装包

1. 从 [GitHub Releases](https://github.com/forfoo-ship-it/aimeiziku/releases/tag/Guikesong) 下载 `AI-Media-Library-Windows-Guikesong.zip`；
2. 解压后双击 `install_windows.cmd`，脚本会创建隔离的 `.venv` 并安装依赖；
3. 按需编辑本地 `.env`，填写视觉模型 API Key；
4. 双击 `start_windows.cmd`；
5. 浏览器访问 <http://127.0.0.1:8000>。

安装需要 Windows 10/11、Python 3.11 或更高版本，以及首次安装依赖时可访问 Python 软件源。FFmpeg 由 `imageio-ffmpeg` 依赖提供，无需单独复制到项目仓库。

若使用系统 Python，可创建虚拟环境并安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

## 测试

```powershell
.\.tools\Python314\python.exe -m pytest -q
```

测试会使用 FFmpeg 生成真实 MP4，验证上传、抽帧、完整视频库分页、首帧缩略图、识别进度、文件夹递归扫描、内容指纹去重、扫描进度、SQLite 时间点和页面访问；搜索与自动识别测试使用固定模拟数据，不连接 DeepSeek，也不消耗真实 API 额度。

## 数据目录

- `data/uploads/`：上传的原视频
- `data/frames/`：按视频分目录保存的关键帧
- `data/media.db`：SQLite 索引数据库

这些运行数据默认不会提交到 Git。

## 内网落地

推荐将服务部署在融媒体中心内网服务器，挂载单位已有素材目录或共享存储。当前版本通过独立 `VisionProvider` 调用视觉模型；正式落地时可替换为内网本地视觉大模型，对历史素材执行首次全量建库，并持续增量索引新增视频。该演进方案不改变编辑端的浏览器使用方式。

当前代码未实现 NAS 专用同步协议、登录权限或公网多租户能力。公网评审以公开源码和 GitHub Release 安装包为交付方式。
